# 库存状态实时同步 - 实施计划

## 需求背景

**问题**：A 用户借用库存后，B 用户的浏览器如果不刷新，显示的还是"在库"状态，无法实时感知库存变化。

**目标**：实现库存状态的实时/近实时同步，让所有在线用户都能看到最新的库存状态。

---

## 方案选择

### 可选方案对比

| 方案 | 实时性 | 代码量 | 复杂度 | 推荐 |
|------|--------|--------|--------|------|
| **轮询 (Polling)** | 10秒 | 15行 | 极简 | ✅ 推荐 |
| SSE | <1秒 | 80行 | 中等 | |
| WebSocket | 实时 | 150行+ | 复杂 | |

### 选择理由

1. **10秒延迟可接受**：库存借用/归还不是高频操作
2. **代码量最小**：改动可控
3. **TanStack Query 内置优化**：页面不可见时自动暂停、不影响性能
4. **虚拟滚动兼容**：只刷新已加载的页，数据不会丢失

---

## 技术方案

### 核心配置

```tsx
// 在 useInfiniteQuery 中添加轮询配置
const { data, fetchNextPage, hasNextPage } = useInfiniteQuery({
  queryKey: ['inventory'],
  queryFn: fetchInventory,
  getNextPageParam: (lastPage) => lastPage.nextCursor,

  // 轮询配置
  refetchInterval: 10000,           // 10秒轮询
  refetchPage: (page, index) => index >= 0,  // 刷新所有已加载的页
})
```

### 轮询行为说明

| 场景 | 行为 |
|------|------|
| 用户查看第1页 | 轮询时更新第1页 |
| 用户翻到第10页 | 轮询时更新所有已加载页（第1-10页） |
| 用户翻回第1页 | 数据已保留，下次轮询更新 |
| 页面不可见（切换标签页） | TanStack Query 自动暂停轮询 |
| 用户离开超过5分钟 | 数据可能被清除，重新加载 |

## 后续优化（可选）

如果未来需要更实时的通知，可升级为 SSE 方案：

1. 后端添加 SSE 端点 `/api/events`
2. 前端使用 `EventSource` 订阅
3. 借用/归还时后端主动推送消息
4. 前端收到消息后立即刷新相关数据
