# PRD.md - 实验室库存管理系统 (LIMS) vFinal

## 1. 项目愿景
构建一个轻量级、高性能的实验室试剂/耗材管理系统。核心解决重复录入问题，通过"订购单 -> 库存"的一键流转，实现对试剂生命周期的精细化管理。

## 2. 核心业务逻辑 (Business Logic)
* **双轨制管理**:
    * **耗材 (Consumables)**: 流程短。`申请` -> `审批` -> `到货确认` (流程结束，不进库存)。
    * **试剂 (Reagents)**: 流程长。`申请` -> `审批` -> `到货确认` -> `入库(生成唯一ID)` -> `借用/归还` -> `耗尽/报废`。
* **唯一性与防重**:
    * **CAS 号**: 作为核心索引。系统必须在后端强制清洗格式（去空格、大写）。在订购时，自动检索库存中相同 CAS 号的剩余总量并预警。
    * **一物一码**: 试剂入库时，若数量为 N，自动生成 N 条独立库存记录，格式为 `CAS号-日期-序号`，若数量为 1，序号根据之前同CAS号的药品序号递增（01开始），全局唯一（包括已用完），便于追踪单瓶状态。

## 3. 用户角色与权限 (RBAC)
* **普通用户**:
    * 查看、查询、编辑、删除条目等常规操作。
    * 发起订购申请。
    * 借用/归还库存（仅限状态操作，不能物理删除）。
    * 执行"入库"操作。
    * 查看个人中心（Dashboard）。
* **管理员**:
    * 除普通用户的权限外，还有如下权限：
        * 审批/驳回申请。
        * 管理用户。
        * 导入/导出 Excel 数据。

## 4. 关键功能模块

### 4.1 个人中心 (Dashboard)
* **设计原则**: 替代手机扫码，作为用户操作的主阵地。
* **模块 A - 我的借用**: 卡片式展示当前用户名下所有"未归还"的试剂。点击"归还"弹出模态框。
* **模块 B - 申请进度**: 列表展示用户发起的订购单状态（已申购/已审批/已到货但未入库）。
* **模块 C - 待入库**: 筛选"已入库但未设置位置"的试剂，方便后续补充位置信息。
* **模块 D - 已到货待入库**: 筛选已到货但未入库的试剂订单。

### 4.2 订购与入库
* **图片处理**: 上传时后端强制压缩至 <100KB，生成缩略图存入文件系统，数据库仅存路径。
* **CAS 预警**: 输入 CAS 号后，前端自动调用接口查询库存，提示"库存中已有 X g，由某某购买"。
* **订购原因**: 订购时必须选择原因（"没有"、"快用完"、"用完"、"常用或公用"、"找不到"、"重新下单"）。
    * "常用或公用"类订单入库后不触发入库提醒通知。
* **暂管入库**: 一键入库时可暂不填写位置信息，系统记录"暂管人"。个人中心提供筛选功能，查看"已入库但未设置位置的试剂"。
* **到货确认**: 用户点击"确认到货"后，试剂订单状态变为"已到货但未入库"，触发入库提醒（常用或公用除外）。

### 4.3 库存管理
* **借用规则**: 只有 `in_stock` 状态的物品可被借用。借用时记录 borrower_id。
* **归还逻辑**: 用户输入"使用量"或"剩余量"，系统自动计算。
    * 若 remaining <= 0，状态变更为 `Consumed`。
    * 若 remaining > 0，状态变回 `in_stock`。
    * **低量预警**: 剩余量 < 20% 时，UI 高亮显示。
    * **借用记录**: 创建 BorrowLog 记录借用/归还时间、数量，显示最近 10 个借用人。
* **耗尽处理**: Consumed 物品不自动删除，但排除在自动统计之外。可在库存列表中查询。
* **位置管理**: 自由文本字段，允许输入"302冰箱第二层"。可留空，后续补充。
* **危险品**: 增加 `is_hazardous` 标记，靠用户自觉管理。
* **Internal Code**: 格式为 `CAS号-日期-序号`（如 `64175-250113-01`），全局唯一，便于物理标签打印。

### 4.4 数据迁移
* 支持 Excel 模板导入（含 CAS、名称、规格、别名、初始量、位置）。
