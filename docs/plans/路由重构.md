# 🚀 Frontend Routing Experience Document: TanStack Router Advanced Practices

## 🎯 背景与核心理念
在构建拥有海量数据和复杂交互的后台系统（如实验室试剂与耗材管理系统）时，路由系统不再仅仅是“切换页面”的工具，而是**全局状态管理的单一事实来源 (Single Source of Truth)**。

本文档总结了从传统 React Router 迁移至 TanStack Router 的核心原因、标准迁移流程，以及如何实现“URL 状态驱动表格与表单”的终极架构。

---

## 一、 为什么选择 TanStack Router 而非 React Router？

在 TypeScript 环境下开发复杂中后台，TanStack Router 是目前的最佳实践。

| 核心维度                   | React Router                                                 | TanStack Router                                              |
| :------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **类型安全 (Type Safety)** | 弱。基于字符串匹配，路径拼错或参数漏传在编译时无感知，容易引发线上白屏。 | **极强**。基于文件生成完整的路由类型树，路径或参数错误直接导致 TS 编译失败。 |
| **Search Params 处理**     | 痛苦。需要手动解析 `URLSearchParams`，全是字符串，无类型校验。 | **优雅**。内置强大的解析器，结合 Zod 实现严格的入参校验，自动转换为 `number`, `boolean` 等精确类型。 |
| **生态融合**               | 需手写大量胶水代码同步状态。                                 | 与 TanStack Table / Query 完美契合，天生支持预加载和数据缓存。 |

## 二、 快速迁移 S.O.P (标准作业程序)

推荐采用**基于文件的路由 (File-based Routing)** 模式，大幅减少手写路由配置的时间。

### 1. 依赖安装与构建配置
引入核心包并配置 Vite 插件，插件会在保存文件时自动生成 `routeTree.gen.ts`。
```bash
npm install @tanstack/react-router
npm install -D @tanstack/router-plugin
```
```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import { TanStackRouterVite } from '@tanstack/router-plugin/vite'

export default defineConfig({
  plugins: [
    TanStackRouterVite(), // 必须在 react() 之前或独立配置，用于拦截文件变化
    react(),
  ],
})
```

### 2. 构建路由树骨架
在 `src/routes/` 目录下建立页面体系：
* **`__root.tsx`**: 根路由包裹器，用于放置全局侧边栏和 `Outlet`。
* **`index.tsx`**: 对应 `/` 路径。
* **`inventory.tsx`**: 对应 `/inventory` 路径。

**根路由示例：**
```tsx
import { createRootRoute, Outlet } from '@tanstack/react-router'

export const Route = createRootRoute({
  component: () => (
    <div className="flex h-screen w-full">
      <nav className="w-64 border-r p-4">系统侧边栏</nav>
      <main className="flex-1 p-6 overflow-auto"><Outlet /></main>
    </div>
  ),
})
```

### 3. 入口文件挂载 (`main.tsx`)
替换旧的 `<BrowserRouter>`，注入生成的路由树并声明全局类型。
```tsx
import { RouterProvider, createRouter } from '@tanstack/react-router'
import { routeTree } from './routeTree.gen'

const router = createRouter({ routeTree })

declare module '@tanstack/react-router' {
  interface Register {
    router: typeof router
  }
}

// render 阶段
<RouterProvider router={router} />
```

## 三、 核心架构：URL 状态驱动长列表 (结合 TanStack Table)

**核心思想**：彻底消灭组件内部用于控制业务状态的 `useState`（如 `page`, `pageSize`, `keyword`）。所有操作修改 URL，URL 的变动触发组件重新渲染和后端数据拉取。

### 1. Zod 定义严格的 URL Schema
在对应的路由文件（如 `inventory.tsx`）中定义参数结构。
```tsx
import { z } from 'zod'
import { createFileRoute } from '@tanstack/react-router'

export const inventorySearchSchema = z.object({
  page: z.number().catch(1),
  pageSize: z.number().catch(10),
  keyword: z.string().catch(''),
})

export const Route = createFileRoute('/inventory')({
  validateSearch: inventorySearchSchema,
  component: InventoryList,
})
```

### 2. 表格状态受控同步
表格组件开启 `manualPagination: true`，直接消费 URL 参数。
```tsx
function InventoryList() {
  const { page, pageSize, keyword } = Route.useSearch()
  const navigate = Route.useNavigate()

  const table = useReactTable({
    // ... 数据与列配置
    manualPagination: true,
    state: {
      pagination: {
        pageIndex: page - 1, // URL (1-based) 转 Table (0-based)
        pageSize,
      },
    },
    onPaginationChange: (updater) => {
      const newPagination = typeof updater === 'function' 
        ? updater({ pageIndex: page - 1, pageSize }) 
        : updater;

      navigate({
        search: (prev) => ({
          ...prev,
          page: newPagination.pageIndex + 1, // 同步回 URL
          pageSize: newPagination.pageSize,
        }),
      })
    },
  })
  
  // 渲染逻辑...
}
```

## 四、 进阶体验：RHF + Zod 实时搜索框

**场景**：输入试剂名称或 CAS 号时，边打字边过滤，不产生冗余网络请求，且保证历史记录的整洁。

**核心机制**：
1. 从 URL 初始化表单默认值。
2. `watch` 监听输入，结合 `useEffect` 实现 500ms 防抖 (Debounce)。
3. 使用 `replace: true` 替换当前路由，避免产生巨量的浏览器后退历史。

```tsx
import { useEffect } from 'react'
import { useForm } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import { z } from 'zod'
import { Route, inventorySearchSchema } from './inventory'

type SearchInput = z.infer<typeof inventorySearchSchema>

export function RealTimeSearchBar() {
  const { keyword } = Route.useSearch()
  const navigate = Route.useNavigate()

  const { register, watch, formState: { isValid } } = useForm<SearchInput>({
    resolver: zodResolver(inventorySearchSchema),
    mode: 'onChange',
    defaultValues: { keyword: keyword || '' },
  })

  const currentKeyword = watch('keyword')

  useEffect(() => {
    const handler = setTimeout(() => {
      if (isValid) {
        navigate({
          search: (prev) => ({
            ...prev,
            keyword: currentKeyword || undefined,
            page: 1, // 搜索词变动，强制重置回第一页
          }),
          replace: true, // 核心：防止破坏浏览器的“后退”功能
        })
      }
    }, 500)

    return () => clearTimeout(handler)
  }, [currentKeyword, isValid, navigate])

  return (
    <input
      {...register('keyword')}
      type="text"
      placeholder="输入关键字进行检索..."
      className="border p-2 rounded-md"
    />
  )
}
```

### 💡 架构优势总结
这套路由机制与后端（如 FastAPI 的 `skip` / `limit` 和 Query 参数）的配合天衣无缝。前端的防抖和 Zod 校验构成了第一道防线，极大地降低了后端的并发压力，同时赋予了系统极高的分享能力（复制链接即刻还原现场）和可维护性。
