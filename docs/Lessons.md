## 2026-03-16: 安全加固应优先替换危险 sink，而非依赖输入来源假设

### 任务描述
按 `1.md` 对全栈项目做安全加固，并保持业务逻辑不变。

### 教训
1. **前端危险渲染口必须先收口**: 遇到 `dangerouslySetInnerHTML` 优先替换渲染路径（如改为 `img + data URI`），不要依赖“当前数据看起来可信”的假设。
2. **安全头要统一出口**: 零散在静态资源或个别路由加 header 容易遗漏，应该集中到全局 middleware。
3. **错误信息要前后端分层**: 前端只收通用错误，内部细节只写服务端日志，避免给攻击者提供探测信息。
4. **文件路径操作必须做根目录约束**: 所有删除/读取文件路径都应先 `resolve` 并验证父目录，防止路径穿越与符号链接逃逸。
5. **SSRF 防护先做低风险硬化**: 在不改业务前提下，先禁重定向并统一外链请求入口，再逐步补主机/IP 白名单。

### 后续行动
- 新增安全扫描清单时，优先覆盖：HTML 注入点、文件路径写删点、外链请求点、错误返回点。
- 每次安全改造后必须运行后端 lint 并提醒前端 lint。

## 2026-03-10: AdminUsers.tsx 修改错误

### 任务描述
将用户管理表格的操作按钮集成到 `TableActionButtons` 组件里，创建独立的 `UserActionButtons` 组件。

### 错误描述
在修改 `frontend/src/pages/AdminUsers.tsx` 时，由于没有完全理解代码结构和依赖顺序，导致文件被破坏无法编译。

### 错误原因
1. **未理解代码依赖顺序**: `columns` 中的 `useMemo` 引用了 `openEditModal`、`openDeleteModal`、`handleActivate`，但这些函数在 `columns` 定义之后才声明，导致 TypeScript 报错 "在赋值前使用了变量"
2. **删除代码时出错**: 在尝试修复依赖顺序时，错误地删除了大量后续代码（`handleDelete`、`handleCreate`、整个 `return` 语句等），导致文件结构被破坏

### 教训
1. **修改前要完全理解代码结构**: 在修改代码前，应该仔细分析代码的依赖关系和执行顺序
2. **分步骤修改**: 应该先添加新组件 → 再修改引用 → 最后删除冗余代码，每一步都要验证后再进行下一步
3. **做好版本控制**: 修改前应该先用 `git stash` 或确保可以快速回退
4. **遇到问题立即回退**: 如果修改遇到问题，应该立即回退而不是继续修改，避免错误累积
5. **不要重复造轮子**: 应该使用已有的 lucide-react 图标库，而不是创建自定义 SVG 组件

### 后续行动
- 恢复被破坏的文件
- 重新规划修改方案，分步骤进行
