# 管理员指南

这一页只讨论管理员专用工作，适合作为值班管理员、实验室负责人和共享终端维护人员的日常操作参考。

## 管理员最常接触的四块工作

管理员日常通常围绕四件事展开：

1. 管用户
2. 管公告
3. 查日志
4. 处理高风险账号和共享终端问题

订单审批、库存导入和库存维护虽然也常由管理员完成，但这些内容在其他用户指南页面已有专门说明，这里重点写管理员专用后台。

## 用户管理

用户管理页是管理员后台里最核心的页面之一。它不仅用于创建账号，也承担了账号筛选、状态管理、资料维护和日志入口等职责。

### 用户列表里能做什么

当前页面支持：

- 查看用户列表
- 搜索用户名和姓名
- 按角色筛选
- 按启用状态筛选
- 分页查看
- 创建用户
- 编辑用户
- 禁用用户
- 激活用户
- 打开指定用户的操作日志

搜索时既可以按用户名查找，也可以按姓名查找。当前登录用户通常会排在靠前位置，便于管理员快速确认自己的身份。

### 创建用户时要决定什么

创建用户时，当前界面会要求你填写：

- 用户名
- 初始密码
- 姓名
- 角色

角色可选：

- `admin`：管理员
- `user`：普通用户
- `public`：公用账户

建议做法：

- 管理员账号数量保持少而稳定
- 普通实验成员默认使用普通用户
- 共享查询电脑、前台终端、公共值班机使用公用账户

### 编辑用户时，管理员能改什么

管理员模式下的编辑弹窗当前支持：

- 修改用户名
- 修改姓名
- 修改角色
- 上传或删除头像
- 修改密码

其中有几个边界要特别注意：

- 如果你修改了某个用户的用户名，该用户现有会话会被全部清掉，需要重新登录
- 管理员不能在当前用户管理页里把自己设为禁用
- 当前页面也禁用了“编辑自己”的快捷入口，避免误操作

### 禁用与激活

当前“删除用户”实际上是软删除，也就是把账号改为停用，而不是物理删除。

禁用后的结果是：

- 账号不能再登录
- 已有会话缓存会被清理
- 后续可以重新激活

这比彻底删除更适合实验室场景，因为很多历史订单、借用、入库记录仍然需要保留责任链路。

### 管理员重置密码时的注意事项

不同账号的密码重置要求并不完全相同：

- 给普通用户重置密码时，不需要旧密码
- 给管理员账号重置密码时，必须提供该管理员账号的旧密码
- 新密码不能和旧密码相同

这意味着，管理员不能在不知道目标管理员旧密码的情况下直接强改另一个管理员密码。这个限制是代码层面的真实安全边界，不是文档约定。

## 公告管理

公告管理页面向管理员开放，用来维护系统内所有站内通知。普通用户只能看公告，不能进这个页面。

### 公告列表里能做什么

当前公告管理页支持：

- 查看所有公告
- 按显示状态筛选
- 按置顶状态筛选
- 创建公告
- 编辑公告
- 删除公告
- 切换置顶 / 取消置顶
- 切换显示 / 隐藏
- 上传公告图片
- 删除公告图片
- 查看公告图片存储占用

页面顶部还会显示当前公告图片的存储占用情况，便于你判断还能不能继续上传较多图片。

### 置顶和显示不是一回事

这是管理员最容易混淆的地方之一。

- `is_visible` 决定普通用户能不能看到
- `is_pinned` 决定它会不会进入顶部置顶横幅

因此，一条公告可能出现这几种组合：

- 可见但不置顶：会出现在公告列表里，不出现在顶部横幅
- 可见且置顶：既出现在公告列表，也会出现在顶部横幅
- 隐藏且置顶：普通用户仍然看不到，因为隐藏优先

### 公告图片相关限制

上传公告图片前会先做基础校验：

- 只能是图片文件
- 单张图片大小有限制

系统还会继续检查：

- 上传频率限制
- 存储容量配额
- 图片文件安全与保存路径

如果你删除一条公告，关联图片也会被一并删除。

### 当前仓库默认的公告配额

按仓库默认配置，单个管理员默认有这些限制：

- 最多 10 条公告
- 最多 5 条“可见公告”

如果你在创建或显示公告时失败，而内容本身没有问题，要优先检查是不是已经达到配额。

### 写公告的建议

推荐这样使用公告系统：

- 真的影响日常操作的消息再置顶
- 过期通知及时隐藏，不要长期挂着
- 标题尽量直接表达结论，不要把关键信息埋在正文里
- 需要截图、排班表、位置图时再上传图片，不要把公告当文件仓库

## 用户操作日志

用户操作日志用于查看某位用户的关键操作记录。通常需要先从 **用户管理** 页面进入，再打开对应用户的日志页。

### 一般进入方式

通常流程是：

1. 在用户管理页点击“查看日志”
2. 系统为该次查看生成临时访问凭证
3. 跳转到日志页面查看该用户的记录

日志页一次只针对一个用户使用。如果页面提示访问无效或已失效，通常重新从 **用户管理** 页面进入即可。

### 日志页能看到哪些类型

当前日志页支持筛选这些类型：

- 试剂订单
- 耗材订单
- 入库记录
- 借用记录
- 常用货架拿取记录
- 登录记录

每条日志不仅有简短摘要，还支持展开查看更完整字段。适合这些场景：

- 确认某个订单何时创建、状态如何
- 回看某人借过什么、是否归还
- 检查某人在哪些设备上登录过
- 追踪常用货架拿取行为

### 管理员看日志时要注意

- 日志页是“针对某个用户”的，不是全站汇总面板
- 看到旧设备记录不代表设备当前还在线，需结合个人账户的会话列表判断
- 登录记录里的 `last_active_at` 与设备管理页看到的最近活跃时间是可相互印证的

## 管理员自己的账户安全

管理员经常在帮助别人管理账号时忽略了自己的会话风险。实际上，你自己的“个人账户”页也很重要。

建议管理员固定做这些事：

- 定期检查自己的设备列表
- 共享电脑用完就退出或踢出其他设备
- 改完密码后清理旧会话
- 不要长期让管理员账号挂在无人的公共终端上

## 管理员日常建议

### 1. 管用户时，先管角色，再管资料

如果一个账号的使用场景本来就是共享终端，就先确认它是不是应该是 `public`，不要先按普通用户建完再补救。

### 2. 不要把“禁用”当作“删除”

停用账号通常已经足够。实验室系统最大的价值之一就是追溯，所以不要轻易追求把人“删干净”。

### 3. 公告系统要克制使用

长期可见公告太多，会让普通用户对未读和置顶逐渐失去敏感度。真正重要的公告反而会被淹没。

### 4. 日志用于追溯，不替代规范流程

日志页能帮助你定位问题，但更好的做法仍然是：

- 要求借用时选真实借用人
- 要求公共终端规范退出
- 要求重要动作留在线上系统里完成
