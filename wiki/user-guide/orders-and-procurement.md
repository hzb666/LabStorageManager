# 订单、采购与入库

## 整体概念

系统将“采购申请”拆分为两条不同链路：

- 试剂订单：适用于带有 CAS 号、规格、危险属性，且后续需要入库与借还追踪的物品。
- 耗材订单：适用于一次性或低值耗材，以采购完成为目标，不自动进入库存。

理解本页时，建议先把流程把握为以下四点：

1. 优先检查库存列表和常用货架。
2. 确认无合适现货后，再创建订单。
3. 试剂到货后仍需继续处理到货、暂存和入库。
4. 耗材审批通过后，通常直接以确认收货或确认完成结束流程。

## 试剂订单页

试剂订单页是完整的试剂采购列表，适用于查询历史、筛选状态、审批和导出。

- 普通用户和管理员均可查看列表。
- 公用账户不能创建试剂订单。
- 页面支持按状态筛选：`待审批`、`已批准`、`已驳回`、`已到货`、`已入库`。
- 页面支持按字段搜索：`CAS号`、`名称`、`品牌`、`订购人`、`订购时间`。
- 管理员可见审批、驳回和导出功能。

### 创建试剂订单时的系统行为

创建弹窗中的关键处理围绕 CAS 号和规格展开：

- `CAS 号` 会先进行格式规范化和校验。
- 可通过 CAS 识别按钮自动补全中文名或英文名。
- 系统会提示当前 CAS 是否已存在于未结束订单或仍有剩余量的库存中。
- 规格会被拆解为数量和单位，供后续入库与借还流程使用。

### 可编辑范围

系统中的一般规则如下：

- 普通用户只能编辑自己的订单。
- 管理员可以编辑全部订单。
- 公用账户不能编辑订单。
- 普通用户的试剂订单进入 `已批准` 或 `已驳回` 后，不再允许编辑，只能删除。
- 管理员可以继续修改订单内容，但状态切换必须通过专门的工作流按钮执行。

### 审批与驳回规则

仅管理员可执行审批或驳回：

- `待审批` 状态可审批。
- `待审批` 和 `已批准` 状态可驳回。
- `已驳回` 状态仍可重新审批。

这意味着被驳回的试剂订单可以重新进入流程，而无需重新创建。

## 耗材订单页

耗材订单页更接近采购清单，不承担后续库存台账职责。

- 普通用户和管理员均可查看。
- 公用账户不能创建耗材订单。
- 页面支持按状态筛选：`待审批`、`已批准`、`已驳回`、`已完成`。
- 页面支持按字段搜索：`名称`、`规格`、`订购人`、`订购时间`。
- 管理员可执行审批、驳回和导出。

### 耗材与试剂的主要区别

- 耗材不强制进入“到货后转库存”的链路。
- 审批通过后，申请人或管理员可直接执行“确认完成”。
- `确认完成` 仅改变订单状态，不生成库存记录。

如某项物品需要后续借还、剩余量更新或位置管理，通常应使用试剂流程，或直接通过库存录入处理，而非将其视作耗材。

### 耗材订单的编辑限制

基本规则与试剂相似，但状态更短：

- 普通用户只能编辑自己的耗材订单。
- 公用账户不能编辑。
- 普通用户在 `已批准` 或 `已驳回` 后不能继续编辑，只能删除。
- 管理员可继续修改内容，但状态流转仍需通过审批或完成操作处理。

## 仪表盘中的订单卡片

仪表盘并非完整历史列表，而是个人当前事项的工作台。

### 我的试剂订单

仪表盘中的试剂标签只显示个人仍在处理中的试剂订单，通常保留以下状态：

- `已申购`
- `已批准`
- `未通过`
- `已到货`

`已入库` 的试剂订单不会继续显示在此处；完整历史需回到“试剂订购”页面查看。

### 我的耗材订单

仪表盘中的耗材标签同样只显示个人仍在处理中的订单，通常保留以下状态：

- `已申购`
- `已批准`
- `未通过`

`已完成` 的耗材订单不会继续占用仪表盘位置。

## 到货、暂存与入库

试剂流程中最容易混淆的部分通常集中在这一环节。

### 路径一：先确认到货，再进入暂存

当试剂订单处于 `已批准` 状态时，申请人或管理员可点击 `到货`。

若到货时尚未填写具体存放位置，系统会：

- 按订单数量生成对应的库存条目。
- 为这些条目记录 `暂存人`，但不写入正式存放位置。
- 将订单状态更新为 `已到货`。
- 使该批记录出现在仪表盘的 `待入库（暂存）` 中。

该路径适用于物品已经送达实验室，但柜位尚未最终确认的场景。

### 路径二：从已批准直接一键入库

在仪表盘试剂标签中，`已批准` 状态的订单除可执行 `到货` 外，也可直接执行 `一键入库`。

系统会：

- 要求填写存放位置和当前剩余量。
- 直接生成正式库存。
- 跳过“已到货但未入库”的中间状态。
- 将订单状态直接更新为 `已入库`。

当柜位和当前剩余量已经明确时，该路径更适合使用。

### 路径三：已到货后补录正式入库

若订单已处于 `已到货` 状态，仪表盘与“待入库”标签页均可继续执行 `入库`。

系统会：

- 找到此前生成的暂存库存。
- 补写正式存放位置。
- 更新当前剩余量。
- 清除暂存人标记。
- 将订单状态更新为 `已入库`。

### 使用要点

试剂的到货与入库并不存在唯一固定顺序：

- 可先到货、暂存，再补录入库。
- 也可在 `已批准` 状态下直接一键入库。

## 待入库模块

待入库模块展示的是仍需补全正式位置的暂存记录，而非完整订单列表。

当前仅显示同时满足以下条件的记录：

- 尚未填写正式存放位置。
- 暂存人是当前登录用户。

因此，该模块表示“当前用户仍未完成落位的库存”，而非“全系统所有待入库订单”。

### 典型操作

- 打开暂存记录
- 补写正式存放位置
- 填写当前剩余量
- 完成入库

### 为什么必须填写剩余量

对于已到货但尚未正式入库的记录，系统要求明确填写当前剩余量，以确保后续库存数据准确。

## 公共 / 常用用途

对于订购原因为 `common_public` 的试剂订单，当前实现存在以下特殊行为：

- 在确认到货时，系统会直接按常用货架库存创建记录。
- 订单会直接进入 `已入库`，不再进入普通暂存流程。
- 使用 `一键入库` 时，生成的库存同样会标记为常用货架物品。

因此，“公共 / 常用试剂”不仅是用途标签，也决定物品最终进入普通库存还是常用货架。

## 购物车导入

购物车导入页是浏览器扩展与站内订单流程之间的桥接页面。

其实际流程如下：

1. 浏览器扩展将抓取到的购物车批次写入浏览器本地存储。
2. 站内 `购物车导入` 页面按 `batch_id` 读取最近批次。
3. 使用者逐项确认导入内容。
4. 每提交一项，系统才真正创建一条试剂订单或耗材订单。

### 页面支持的操作

- 逐项浏览待导入商品
- 在 `试剂` 和 `耗材` 表单之间切换当前项类型
- 删除当前项并放弃导入
- 逐项提交

### 默认判断规则

导入页会先根据商品信息是否可提取 CAS 号进行预判：

- 能提取 CAS 号时，默认按试剂处理。
- 无法提取 CAS 号时，默认按耗材处理。

该默认判断可由使用者手动调整。

### 其他自动辅助能力

- 试剂项可继续使用 CAS 识别。
- 若存在 CAS 号但缺少英文名，页面会尝试自动补全英文名。
- 试剂项仍会执行 CAS 重复提醒。

### 需要关注的限制

- 公用账户不能导入购物车订单。
- 批次数据有效期为 2 小时，过期后需由浏览器扩展重新发起。
- 批次号不匹配会被系统拒绝。

### 使用方式说明

购物车导入并非抓取后自动批量生成订单，而是先进入导入页面逐项确认，再生成正式订单。

## 典型流程示例

### 流程一：普通试剂，从申请到正式入库

1. 在库存管理或常用货架中搜索 CAS 号和名称。
2. 确认无合适现货后，创建试剂订单。
3. 由管理员审批。
4. 到货后，由申请人或管理员选择以下方式之一：
5. 若柜位未定，先执行 `到货`，使其进入暂存。
6. 若柜位和剩余量已确认，直接执行 `一键入库`。
7. 如使用暂存路径，再在仪表盘 `待入库` 中补写正式位置和剩余量。
8. 订单变为 `已入库`，后续转由库存管理页面承接。

### 流程二：公共试剂，直接进入常用货架

1. 创建试剂订单时将用途设置为公共 / 常用相关原因。
2. 审批通过后，由申请人或管理员确认到货。
3. 系统直接将该批次生成常用货架库存。
4. 订单直接完成入库，不再进入普通待入库列表。

### 流程三：耗材，从采购到完成

1. 在耗材订购页创建订单。
2. 由管理员审批或驳回。
3. 物品到货后，由申请人或管理员点击 `确认收货` 或 `确认完成`。
4. 状态更新为 `已完成`，流程结束。

## 搜索与筛选建议

- 跟踪某项试剂是否重复采购时，优先使用 `CAS号` 搜索。
- 查询个人近期处理中事项时，优先查看仪表盘。
- 查询完整历史或执行导出时，返回“试剂订购”或“耗材订购”主页面。
- 试剂订单页的展开行适合查看英文名、别名与备注等补充信息。
- 仪表盘中的订单标签适合处理“当前要做什么”，不适合作为历史归档入口。

## 常见疑问

### 为什么某条旧订单未出现在仪表盘

仪表盘仅保留处理中状态：

- 试剂订单不再显示 `已入库`
- 耗材订单不再显示 `已完成`

完整历史需返回对应订单主页面查看。

### 为什么点击到货后，仍未在正式库存中搜索到

常见原因包括：

- 该条记录已进入暂存，尚未正式入库。
- 该物品属于公共 / 常用用途，已进入常用货架。
- 当前搜索条件过窄，未命中目标记录。

建议依次检查：

1. 仪表盘中的 `待入库`
2. 常用货架
3. 库存列表的搜索条件

### 为什么购物车导入后仍需逐项确认

当前实现采用“半自动导入”方式：

- 扩展负责抓取数据。
- 页面负责校正类型、补全字段和逐项提交。

这样可降低错误规格、错误类型或占位名称直接进入正式订单的风险。
